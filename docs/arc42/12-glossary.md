# 12. Glossary

This glossary provides definitions for key terms, concepts, and abbreviations used throughout the Public UI - KoliBri architecture documentation. It serves as a reference to ensure consistent understanding across all stakeholders.

## A

**Accessibility (A11y)**  
The practice of making web content usable by people with disabilities. Public UI - KoliBri focuses on meeting WCAG 2.2 Level AAA standards.

**Adapter**  
Framework-specific wrapper around KoliBri components. Auto-generated by Stencil output targets for React, Angular, Vue, etc.

**Adopted Style Sheets**  
Web API that allows sharing style sheets across multiple shadow DOM instances. Used by KoliBri for efficient theming.

**ARIA (Accessible Rich Internet Applications)**  
Set of attributes that define ways to make web content more accessible to people with disabilities.

**Atomic Component**  
Small, single-purpose component (button, input, icon) that can be composed into larger components. KoliBri focuses on atomic components.

## B

**BEM (Block Element Modifier)**  
CSS naming convention used in KoliBri's styling. Example: `.kol-button__icon--small`

**BITV (Barrierefreie-Informationstechnik-Verordnung)**  
German accessibility regulation that KoliBri complies with. Based on WCAG standards.

**Bundle Size**  
Total size of JavaScript and CSS files. KoliBri optimizes bundle size through lazy loading and code splitting.

## C

**Component**  
Reusable UI element with encapsulated structure, styling, and behavior. In KoliBri, refers to Web Components.

**Component Library**  
Collection of reusable components. KoliBri is a component library for accessible HTML.

**CSP (Content Security Policy)**  
Security standard that helps prevent XSS attacks. KoliBri components are CSP-compatible.

**Custom Element**  
Web standard for defining new HTML elements. KoliBri components are custom elements (e.g., `<kol-button>`).

**Custom Element Manifest**  
JSON file describing custom elements' APIs. Generated by Stencil and used for documentation and IDE support.

## D

**Declarative Shadow DOM**  
Server-side rendering technique for Web Components. KoliBri has limited support currently.

**Design System**  
Set of reusable components and design guidelines. KoliBri provides foundation for design systems.

**Design Token**  
Named value (color, spacing, font) used in design systems. KoliBri themes use design tokens.

**DX (Developer Experience)**  
How easy and pleasant it is to use a tool or library. KoliBri prioritizes good DX.

## E

**Encapsulation**  
Isolation of component implementation from outside code. Achieved through Shadow DOM.

**EUPL (European Union Public License)**  
Open source license used by KoliBri (version 1.2).

**Event**  
Signal emitted by component when something happens (click, change, etc.). KoliBri uses CustomEvent API.

## F

**Framework Adapter**  
Package that makes KoliBri components work naturally in specific frameworks (React, Angular, Vue).

**Framework-Agnostic**  
Works with any or no framework. Core principle of KoliBri.

## H

**Hydration**  
Process of attaching event handlers to server-rendered HTML. Relevant for SSR scenarios.

## I

**ITZBund (Informationstechnikzentrum Bund)**  
German federal IT service provider that created and open-sourced KoliBri.

## J

**JSX (JavaScript XML)**  
Syntax extension for JavaScript used in Stencil component templates.

## K

**KoliBri**  
Component Library for Accessibility - the name of this project. Always spelled with this casing.

## L

**Lazy Loading**  
Loading code only when needed. KoliBri components are lazy-loaded for optimal performance.

**LTS (Long-Term Support)**  
Version supported for 3 years. Provides stability for enterprise users.

**Loader**  
JavaScript module that defines custom elements. KoliBri provides loader for lazy loading.

## M

**Monorepo**  
Single repository containing multiple packages. KoliBri uses pnpm workspace monorepo.

**Multi-Theming**  
Ability to apply different visual themes to same components. Core KoliBri feature.

## N

**npm (Node Package Manager)**  
Package registry where KoliBri packages are published.

**Nx**  
Build system for monorepos. KoliBri uses Nx for build orchestration and caching.

## O

**Output Target**  
Stencil configuration for generating framework adapters. KoliBri uses output targets for React, Angular, Vue, etc.

## P

**pnpm (Performant npm)**  
Fast, disk-efficient package manager. KoliBri uses pnpm workspaces.

**Polyfill**  
Code that provides functionality not natively supported by browsers. May be needed for older browsers.

**Props (Properties)**  
Configuration options passed to components. KoliBri uses underscore prefix (e.g., `_label`).

**Provenance**  
Build attestation proving package authenticity. KoliBri publishes with SLSA Build Level 3 provenance.

## R

**React**  
Popular JavaScript framework. KoliBri provides React adapter.

**Responsive**  
Adapts to different screen sizes. KoliBri components are responsive by default.

**RTL (Right-to-Left)**  
Text direction for languages like Arabic and Hebrew. KoliBri supports RTL layouts.

## S

**SASS (Syntactically Awesome Style Sheets)**  
CSS preprocessor used for KoliBri themes.

**Screen Reader**  
Assistive technology that reads web content aloud. KoliBri ensures screen reader compatibility.

**Semantic HTML**  
Using HTML elements according to their meaning (button for buttons, not div). KoliBri enforces semantic HTML.

**SemVer (Semantic Versioning)**  
Versioning scheme (MAJOR.MINOR.PATCH). KoliBri strictly follows SemVer 2.0.

**Shadow DOM**  
Web standard for encapsulating component DOM and styles. Core to KoliBri's architecture.

**SLSA (Supply-chain Levels for Software Artifacts)**  
Security framework for software supply chains. KoliBri aims for Build Level 3.

**Slot**  
Web Components mechanism for content projection. Used for flexible component composition.

**SSR (Server-Side Rendering)**  
Rendering components on server. KoliBri has limited SSR support via hydrate adapter.

**Stencil**  
Web Component compiler used to build KoliBri. Developed by Ionic team.

**STS (Short-Term Support)**  
Version supported for 15 months. Enables rapid innovation.

## T

**Theme**  
Package containing visual styles for components. KoliBri separates themes from component logic.

**Tree Shaking**  
Removing unused code during bundling. KoliBri supports tree shaking for smaller bundles.

**TypeScript**  
Typed superset of JavaScript. All KoliBri code written in TypeScript.

## V

**Vue.js**  
Progressive JavaScript framework. KoliBri provides Vue adapter.

## W

**W3C (World Wide Web Consortium)**  
Standards organization for the web. KoliBri follows W3C standards.

**WCAG (Web Content Accessibility Guidelines)**  
International accessibility standards. Public UI - KoliBri implements WCAG 2.2 Level AAA.

**Web Component**  
Set of web standards for creating reusable custom elements. Foundation of KoliBri.

**Web Standard**  
Official specification from W3C. KoliBri built on web standards for longevity.

## Component Naming

All KoliBri components are prefixed with "Kol" to avoid naming conflicts:

- `<kol-button>` - Button component
- `<kol-input-text>` - Text input component
- `<kol-table>` - Table component
- `<kol-modal>` - Modal dialog component
- etc.

## Property Naming

Component properties are prefixed with underscore to avoid conflicts with native HTML attributes:

- `_label` - Component label
- `_disabled` - Disabled state
- `_variant` - Visual variant
- `_icons` - Icon configuration
- etc.
