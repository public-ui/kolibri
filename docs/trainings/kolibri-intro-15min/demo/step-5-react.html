Diese Seite ist ein Code-Vergleich – hier läuft absichtlich kein KoliBri und kein React. Die lebendigen Komponenten stehen auf den Schritten 1 bis 4.

Vanilla – was wir gerade gebaut haben

<!-- einmal beim Start -->
import { register } from '@public-ui/components';
import { defineCustomElements }
  from '@public-ui/components/loader';

await register(DEFAULT, defineCustomElements);

<!-- im Markup -->
<kol-form>
  <kol-input-email
     _label="E-Mail"
     _required
     _max-length="120"></kol-input-email>
  <kol-button
     _label="Absenden"
     _variant="primary"
     _type="submit"></kol-button>
</kol-form>

React – derselbe Baukasten

// einmal beim Start
import { register } from '@public-ui/components';
import { defineCustomElements }
  from '@public-ui/components/loader';
import { DEFAULT } from '@public-ui/theme-default';

await register(DEFAULT, defineCustomElements);

// in der Komponente
import { KolForm, KolInputEmail, KolButton }
  from '@public-ui/react-v19';

<KolForm _on={{ onSubmit }}>
  <KolInputEmail
     _label="E-Mail"
     _required
     _maxLength={120} />
  <KolButton
     _label="Absenden"
     _variant="primary"
     _type="submit" />
</KolForm>
Der einzige echte Unterschied steht kursiv: In HTML gibt es kein camelCase, dort heißt die Prop _max-length. In JSX schreibt man _maxLength. Alles andere – Props, Verhalten, ARIA-Verdrahtung, Theme – ist identisch, denn darunter läuft in beiden Fällen dieselbe Web Component.

Adapter gibt es für React, Angular, Vue, Svelte, Solid und Preact. Sie sind dünne Hüllen um genau die Elemente, die wir hier in reinem HTML benutzt haben.
Wiederverwendung eine Ebene höher: Weil die Komponenten normale Bausteine sind, baut man daraus eigene. Der react-hook-form-Adapter von KoliBri macht genau das – er verheiratet jedes Eingabefeld mit der Formular-Bibliothek und reicht Validierungsfehler automatisch als _msg und _touched weiter. Aus Bausteinen werden eure Bausteine.
